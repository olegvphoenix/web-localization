# 07 — Задачи

Десять задач в шести проектах Jira. Ни одна ещё не заведена: сначала
вычитка здесь, потом заведение.

Постановки ниже короткие — это черновики текстов задач. Подробности — в
разделах, на которые они ссылаются.

Отдельно: в DANV-9122 и PMD-6243 пересчитать оценку по задачам этого
документа и убрать из описания фразу «переводы не попадают в продукт» — этот
дефект исправлен 24.09.2026 (DANV-9171), см. [01](01-current-state.md).

## Как разбито

**Одна задача — один законченный результат.** Загрузчик, сверка и правила
приложения выходят вместе: по отдельности ни одна из этих частей не
работает. Поэтому переключение приложения — одна задача, и обязательная
проверка на PR — одна задача вместе со скриптом, который она запускает.

**Правила проверок уже записаны** в [04](04-validation.md) и переходят в
постановки Т4 и Т8; отдельного документа-контракта нет.

**Репозиторий переводов раньше приложения.** Приложение нечем переключать, пока
переводы не лежат в репозитории переводов и не проверены.

**Переключение выгрузки Crowdin — отдельная граница.** До неё переводы приходят
в приложение как сегодня, после — только в репозиторий переводов. Поэтому она
идёт сразу перед переключением приложения, а не раньше: Т6 — перед Т8.

**Разработчик не следит за выходом переводов.** Новую версию пакета в
приложение приносят сборщики (Т7) — порядок записан до переключения
приложения.

## Этап 0 — предусловия

### Т1а · Защита основной ветки репозитория переводов

Настроить в Bitbucket защиту основной ветки `localizationpackages`:
разработчики — чтение; локализация пишет только через PR с ревью; без прямого
push и force-push; ветку выгрузки Crowdin вливает лид локализации.
Обязательную проверку на PR подключает Т4, здесь её нет.

**Готово, когда:** прямой push и force-push в основную ветку отклоняются, PR с
ревью вливается.

### Т1б · Право публиковать npm и запрет `@axxon-l10n` извне

Дать плану переводов NS-LOCPAC право публиковать npm-пакеты `@axxon-l10n/*` в
`npm-local` Artifactory — туда же, где лежат `@axxon-web/*`; план сборки
веб-клиента уже читает оттуда. Если виртуальный npm-репозиторий
Artifactory проксирует npmjs — запретить брать `@axxon-l10n` из публичного
реестра.

**Готово, когда:** план переводов публикует пробный пакет `@axxon-l10n/*` в
`npm-local`; запрос `@axxon-l10n` через виртуальный репозиторий не уходит
наружу.

### Т2 · Эталонный список кодов языков и описание языков

Коды языков расходятся между репозиторием переводов, настройками Crowdin и
сборкой WinForms-клиента: греческий, китайские, португальские, мексиканский
испанский. Нужен один список с точностью до регистра — он станет именами файлов
в репозитории переводов. Отдельно решить регистр: имена файлов строчными
(`zh-hant`) или как у сервера и `RequestedLanguages` (`zh-Hant`), и откуда
берётся вид для заголовка `Accept-Language`. Там же определить формат
описания языков в пакете: коды и псевдонимы тегов браузера. Какие языки
выпускать, решает не описание, а список в приложении — см. Р9 в
[03](03-decisions.md).

**Готово, когда:** список, регистр и формат записаны в [06](06-appendix.md).

## Этап 1 — репозиторий переводов

### Т3 · Переводы веб-клиента в репозитории переводов

Перенести текущие переводы веб-клиента всех языков в репозиторий переводов под
кодами из Т2. Место для них заводят сопровождающие репозитория переводов.
Английский не переносится: нынешний отдельный английский файл веб-клиента в
пакет не попадает, английский — `strings.json` приложения. Переносить из Crowdin, чтобы не потерять правки,
пришедшие в репозиторий приложения. Создать файл описания языков — коды и
псевдонимы тегов браузера в формате из Т2; по нему проверка из Т4 сверяет
набор файлов.

**Готово, когда:** переводы веб-клиента и описание языков лежат в репозитории
переводов, число строк по каждому языку совпадает с Crowdin.

### Т4 · Обязательная проверка на PR и npm-пакет в плане переводов

Подключить к основной ветке репозитория переводов обязательную проверку на PR:
PR без пройденной проверки не вливается. Проверка смотрит целостность файлов:
разбирается ли JSON, нет ли повторяющихся ключей, совпадает ли набор файлов с
описанием языков, нет ли в папке английского файла. В отчёте — файл, ключ,
что не так, и список ключей, изменившихся в этом PR. Правила и уровни — «Что
именно проверяется» и «Правила проверок» в [04](04-validation.md).

Плейсхолдеры и ICU здесь не проверяются — это делает Crowdin при сохранении
строки. Утилита проверки ресурсов WinForms-клиента не используется, см. Р10 в
[03](03-decisions.md).

Добавить в стадию Publish плана переводов публикацию npm-пакета
`@axxon-l10n/webclient` — той же версии `1.0.<номер сборки>`, что NuGet-пакеты
WinForms-клиента. В пакет входят JSON переводов веб-клиента и описание языков.
Публикация NuGet не меняется. Пакет публикуется, только если папка веб-клиента
менялась с прошлой публикации: иначе каждая публикация WinForms даёт новую
версию веба, и предупреждение «есть версия новее» в сборке приложения горит
всегда.

Сегодня в плане нет Node: он собирается Ant и MSBuild и публикует только
NuGet в `nuget-local`. Нужно одно из двух — Node и npm на агенте плана или
выкладка готового архива пакета в Artifactory через REST. Это часть задачи, а
не мелочь.

**Готово, когда:** проверка обязательна в настройках ветки; PR с испорченным
JSON или повторяющимся ключом не вливается, в отчёте видны файл, ключ и что не
так; запуск Publish после изменений веба публикует NuGet и npm-пакет одной
версии; запуск без изменений веба npm-пакет не публикует.

## Этап 2 — Crowdin

### Т5 · Crowdin sync: источник из одного репозитория, выгрузка в другой

Для веб-проекта утилита синхронизации должна читать английский источник из
репозитория приложения, а выгружать переводы в репозиторий переводов — только
целевые языки, без английского.
Проверить, что это возможно; если нет — доработать или предложить переход на
родную интеграцию Crowdin (`crowdin.yml`), как в Drivers Pack.

**Готово, когда:** на пробной ветке источник читается из приложения, а
выгрузка приходит в репозиторий переводов, — или принято и записано решение
перейти на родную интеграцию Crowdin через `crowdin.yml`.

### Т6 · Crowdin: выгрузка Web Client в репозиторий переводов

Непосредственно перед Т8 перенастроить проект Web Client: переводы
выгружаются в репозиторий переводов, в репозиторий веб-клиента больше не
выгружаются. Источник по-прежнему читается из репозитория веб-клиента.
Выгружаются только целевые языки: английский как целевой язык для Web Client
не выгружается и не редактируется. Первая выгрузка — полная, всех целевых
языков, PR в защищённую ветку.

Выбрать режим синхронизации источника: «Keep translations» — перевод
изменённой строки остаётся и помечается проверкой «Outdated translations», или
«Clear all translations and approvals» — перевод стирается и до нового
перевода пользователь видит английский разработчика. Решение за DDOC, см. Р12 в
[03](03-decisions.md).

С этого момента файлы переводов в репозитории веб-клиента заморожены до
Т8. О заморозке объявляет лид локализации владельцам веб-клиента в день
переключения.

**Готово, когда:** полная выгрузка пришла в репозиторий переводов, а в
репозиторий веб-клиента новых коммитов переводов нет; заморозка объявлена;
после изменения английского текста строки её перевод ведёт себя по выбранному
режиму — помечен устаревшим или стёрт.

## Этап 3 — приложение

### Т7 · Порядок сборщиков: публикация, подъём, откат

Записать в порядок работы сборщиков, рядом с `LocalizationVersion`
WinForms-клиента:

1. **Публикация.** Publish плана переводов после тикета локализатора. npm-пакет
   выходит, только если менялась папка веб-клиента (Т4); нет новой версии —
   поднимать нечего.
2. **Подъём.** Один коммит в `package.json` и lockfile веб-клиента с ключом
   тикета локализатора или постоянного тикета подъёма версий
   ([ACR-86237](https://support.axxonsoft.dev/jira/browse/ACR-86237)).
   Сначала `master`, затем релизные ветки, которым нужен этот перевод, — от
   новой к старой; ветка, которой перевод не нужен, держит свою версию.
3. **Откат.** Плохой, но формально верный перевод. Полный откат такой: вернуть
   прежнюю версию пакета, собрать веб-клиент, поднять
   `component.webClient.build` в `ngp.axxon`, собрать сервер.
4. **Замена.** Кто делает подъём и откат, когда сборщика нет.

Отдельно проверить, что у сборщиков есть право записи в репозиторий
веб-клиента, и выдать его, если нет.

**Готово, когда:** порядок записан; права записи сборщиков в репозиторий
веб-клиента проверены.

### Т8 · Веб-клиент: переводы из репозитория переводов

Список выпускаемых языков веб-клиента — решение продукта, принятое до начала
задачи (Р9 в [03](03-decisions.md)). Задача вносит его в приложение.

**Исключение из D-15.** Решение D-15 закрывает `package.json` разработчикам.
Для этой задачи сделано исключение: разработчик один раз вносит в
`package.json` первую запись пакета и парсер ICU в `devDependencies`. Дальше
версию пакета меняют только сборщики (Т7).

**Подключение пакета.** Веб-клиент подключает пакет `@axxon-l10n/webclient`
точной версией как необязательную зависимость. В `.npmrc` добавить строку
`@axxon-l10n:registry=https://artifactory.itvgroup.ru/artifactory/api/npm/npm-local/`
— сегодня там только `@axxon-web`. Без неё npm возьмёт пакет из публичного
реестра, см. Р1 в [03](03-decisions.md). В lockfile `resolved` пакета должен
указывать на Artifactory.

**Загрузка.** Плагин сборки Vite отдаёт языки из `node_modules` виртуальным
модулем; загрузчик берёт из него переводы и описание языков; пакета нет —
остаётся английский источник. Строка ищется по порядку из
[02](02-proposal.md): перевод, затем английский из `strings.json`; слоёв OEM
нет — брендовых строк у веб-клиента нет. Язык выбирается по порядку: язык →
псевдоним из описания языков → язык без региона → английский. Сегодня
веб-клиент ищет файл по языку браузера целиком, и `en-US`, `pt-PT`, `es-419`,
`de-AT` своего файла не находят — пользователь видит английский разработчика.
После задачи они получают свой язык, а любой английский тег — английский из
`strings.json`, см. Р5 в [03](03-decisions.md). `DISABLED_LANG` по-прежнему отключает языки. Файлы
переводов удаляются, кроме английского источника; тесты, которые сегодня
читают файлы языков напрямую, в том числе отдельный английский файл,
переводятся на английский источник.

**Сверка с источником.** Плагин сборки сверяет имена аргументов ICU в каждой
строке переводов из пакета с английским источником — разбором, а не
регулярным выражением, по правилам из [04](04-validation.md). Содержимое
перевода не проверяется. Строка с расхождением в сборку не попадает, для этого
ключа показывается следующий слой; в журнал и в файл-артефакт пишется
предупреждение: язык, ключ, что ожидалось, что получено. Языки списка без
файла и файлы без языка в списке — тоже предупреждение (Р9). Сборка из-за
переводов не падает; в журнал пишется версия пакета и предупреждение, если в
Artifactory есть версия новее. При локальной разработке те же предупреждения в
консоли, но строки не отбрасываются.

**Нет пакета.** npm молчит: необязательной зависимости нет — `npm ci`
завершается с кодом 0 без предупреждения. Отсутствие пакета замечает сам
плагин и пишет предупреждение. На сборке выпуска — метка: заметная строка
предупреждения в журнале сборки Bamboo и метка Bamboo на сборке, например
`l10n-missing`.

**Правила.** Для разработчиков и ИИ-агентов: строки пишутся только в
английский источник; меняешь текст — меняешь его в том же ключе; на новые и
изменённые строки — задача на локализацию с контекстом; файлы переводов,
список языков и версию пакета разработчики не трогают. Обновить инструкцию по
добавлению строк и решение о ключах переводов. Отдельно: ключи, на которые
ссылаются OEM-компоненты вендоров, не переименовываются и не удаляются без
согласования с сопровождающими OEM-ресурсов.

**Готово, когда:** сборка на Bamboo ставит пакет из Artifactory, `resolved` в
lockfile указывает на Artifactory; все языки из списка выпускаемых
показываются из пакета; пользователь с `en-US` видит английский из `strings.json`, с
`pt-PT` — португальский; без пакета сборка проходит на английском с
предупреждением плагина и меткой на сборке выпуска; строка с изменённым
плейсхолдером показывается по-английски с предупреждением; сборщик сделал
пробный подъём версии по Т7, и сборка прошла; в репозитории остался только
английский источник; правила обновлены.

## Этап 4 — права

### Т9 · Права локализаторов в репозитории веб-клиента

Локализаторам больше не нужна запись в репозиторий веб-клиента: переводы
туда не приходят. Чтение остаётся — оно нужно синхронизации источника с
Crowdin.

**Готово, когда:** у локализаторов нет записи в репозиторий веб-клиента,
чтение осталось.
